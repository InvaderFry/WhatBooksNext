# Milestone 0 — Windows probe

**Status:** done. The owner ran the probe on 2026-11-08 and shared the report in chat.
iCloud placeholders couldn't be tested because iCloud isn't installed on the PC (see below).

## What was built

- `tools/probe/whatbooks-probe.bat`: a read-only `.bat` with the PowerShell part embedded
  as plain text. It runs with `-NoProfile -ExecutionPolicy Bypass` for this script only.
  It's compatible with Windows PowerShell 5.1, so nothing needs installing. How to run it:
  `tools/probe/README.md`.
- `.gitignore` entries for probe reports, `fixtures/private/`, `docs/private/` and `data/`,
  so the owner's library stays out of this public repo.
- `.gitattributes` forces CRLF for `.bat` files.

What the report covers, mapped to the plan:

| Plan assumption | What the probe reports |
| --- | --- |
| §9.4 drive identity | Per folder: drive letter, volume label, `Win32_Volume` GUID and serial, `Get-Volume` UniqueId, drive type, partition GUID, disk bus type (USB or not). |
| §9.5 placeholder bits | Per folder: book-file counts by state, counts per recall/offline/pinned/unpinned bit, and the 15 most common **raw attribute numbers** with decoded names. Files that report size 0 (this would break name+size copy matching). |
| §9.5 attributes don't trigger downloads | For 2–3 owner-named online-only files, attributes before and 10 s after. Only `File.Exists`/`File.GetAttributes` are called. Neither opens the file. |
| §11.3 copies | Groups with the same name (ignoring case) and exact size in more than one directory: how many span folders, mix online-only and local copies, or have 3+ copies. Same name with different sizes. |
| §11.3 format groups | Same directory + same base name (quality tags removed) groups, by extension combination. HD groups, and base names in several directories split into pure copies and review suggestions. |
| §11.1 filename shapes | Title-free counts of shapes (run-together, underscores, `Author - Title`, years, volume/issue markers, non-ASCII), paths of 260+ characters. |
| §13.7 bulk-copy dates | The share of files on the most common modified/created day, "created after modified", and directories where most files share one day. |
| M1 prerequisites | Windows build, PowerShell version, CPU cores, long-path setting, Node.js version, iCloud/OneDrive presence. |

Folders are listed with `DirectoryInfo.GetFileSystemInfos()`, which takes names, sizes, dates
and attributes from the directory listing without opening any file. Junctions and symlinks
are skipped. Other reparse-point directories (cloud placeholders) are followed, with
a depth limit (64) and a total-directory cap (200,000) as extra loop protection.

## How it was checked

- The embedded PowerShell parses cleanly (PowerShell 7.4 parser).
- It ran end to end under PowerShell 7.4 on Linux against an invented fixture folder
  (EPUB+PDF+MOBI trio, HD + standard CBZ, a cross-folder copy, a same-name/different-size
  file, a symlink loop). The counts matched the fixture. The loop was skipped. When the
  script sat inside a library folder, nothing was written there.
- **Not checked:** Windows PowerShell 5.1 itself, `cmd.exe` launching, real iCloud
  placeholders, `Get-Volume`/`Get-Partition`, and the `LinkType` property under 5.1. All of
  these **need checking on the owner's machine**. Running the probe is that check.

## Findings (title-free)

From the owner's report. Probe version 1, Windows 11 Home build 26300, PowerShell 5.1, 16 cores.

**PC**
- Long paths are enabled. Node.js isn't installed (needed for M1). OneDrive is set up.
- **No iCloud**: no iCloud process and no iCloud Drive folder. The owner uploads most local books
  to iCloud and reads them on the iPhone and iPad. Store purchases are in Apple Books, Kindle and
  Google Play Books.

**Drive identity (§9.4): confirmed**
- One library folder, on an 8 TB external USB drive (NTFS, GPT).
- `Win32_Volume`, `Get-Volume` and `Get-Partition`/`Get-Disk` all worked without admin rights.
  Volume GUID path, partition GUID and volume serial were all available. The volume GUID and
  partition GUID match.
- Windows reports the drive type as **Fixed (3)**, not Removable, while the bus type is **USB**.
  So the app must use the bus type to recognise an external drive.
- Drive-letter changes are still untested.

**Attributes (§9.5): not testable here**
- Of 3,842 book files, 3,841 are `0x20` (Archive) and 1 is `0x120` (Archive, Temporary). There are
  no reparse points, recall bits, Offline bits or pinned/unpinned bits.
- The online-only check was skipped, because there's no iCloud. The plan's bit rules are
  unconfirmed on real files. The fakes will use the documented values.
- One local book file has size 0 (a Library health case).

**Contents**
- About 8,000 files in 474 directories, listed in 7.9 s by PowerShell.
- Book files: 1,364 EPUB, 2,041 PDF, 399 CBR, 37 CBZ, 1 MOBI, no AZW3 or CB7. MOBI, AZW3 and CB7
  barely matter for this owner.
- Others: mostly audio (mp3, flac, wav, aa) and images. Also **124 `.zip` and 60 `.rar`**, which
  might be comics or bundles. Asked the owner.
- No paths of 260+ characters (longest 234). No non-ASCII filenames.

**Copies and format groups (§11.3): rules hold, at scale**
- 262 name+size groups appear in several directories (546 files, 22 groups with 3+ copies).
  All are on the same drive. 8 names appear in several directories with different sizes.
- 1,147 same-directory format groups: 1,135 EPUB+PDF, 6 CBZ+PDF, 3 CBR+PDF, 2 CBZ+EPUB+PDF,
  1 PDF+PDF. Rule 2 removes about 1,150 would-be review rows.
- 180 base names appear in several directories: 138 are identical sets (copies) and 42 differ
  (rule 3 suggestions, about 1% of books).
- Only 11 files carry an HD-style quality tag. Size tags (`optimized`, `high`, `downsampled`) and
  Humble numeric ids are more common, so the parser rules were extended.

**Filename shapes (§11.1)**
- 50% of names have underscores, 33% are run-together lowercase, 13% have spaces, 34% have a volume
  marker, 8% an issue number, 9% a year, 5% bracket tags, and 0.8% use `Author - Title`.
- Two families: Humble-style slugs (`series_volN_subtitle`, `title_issueN`) and scene-style comic
  names (`Series 005 (2002) (Digital) (Group).cbr`, `Series V1 17.cbr`, and issue files naming
  their trade volume and arc). New parser rules and invented fixtures are in PLAN.md §11.1.
- Some files aren't books (character sheets) and some are tabletop RPG books. These fall under
  Library health, unidentified items and the reference flag. No new kind is needed yet.

**File dates (§13.7)**
- 98.9% of book files were created later than they were modified, so the drive was filled by
  copying. Created dates are useless. Modified dates are kept.
- Across the whole folder, the most common modified day covers 3.9% of files. But in 114 of 115
  directories with 10+ books, most files share one modified day: one bundle, one download day.
  The bulk-copy rule therefore moves to the library-folder level (PLAN.md §13.7, §20).
