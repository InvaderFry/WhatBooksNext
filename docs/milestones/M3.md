# Milestone 3: first real recommendations

**Status:** built, and the done-when checks that can run without the owner pass in the sandbox.
One owner step remains: the **first quality session** (end of this note). The Hardcover test
passed (last section). No new dependencies.

## What was built

- **Online sources (PLAN.md §12.1)** in `server/src/sources/`. One client per source
  (`client.ts`): one request at a time with a minimum gap, obeys `Retry-After` and rate-limit
  headers, caches raw responses in `source_cache`, and pauses a source for 10 minutes after 5
  failures in a row (circuit breaker). A failure never erases candidates already found.
  - **Open Library** (no key): search by title + author, or by an EPUB's ISBN.
  - **AniList** (no key): manga, searched by series name. Its score is for the whole series, so
    it's stored with scope `series` and always shown as "Series rated …".
  - **Hardcover** (optional token): book search with rating, vote count, pages, series position
    and genres. One request per book.
  - **Demo source**: invented records for the invented demo books, labelled "Demo source
    (invented)". The demo never goes online.
- **What was verified about each source (November 2026):**

  | Source       | Checked                                                     | Findings                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
  | ------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Open Library | openlibrary.org/developers/api, search and covers docs      | 1 request/s without a contact email (3/s with one; we send none, §5).   | AniList      | the live API                                                | No key needed. - **Matching (§11.2)** in `identify/match.ts`. Title (articles, spaces and punctuation ignored,
  raw run-together names too), author at surname level, and ISBNs: an EPUB's own ISBN is strong
  evidence, a PDF's ISBN only corroborates. Thresholds 0.90 / 0.60 and the 0.05 tie margin are
  from §20. Calibration:
  - an exact title with an agreeing author scores 1.0 (accepted);
  - an exact title with no author to check scores 0.85 (provisional, shown "unconfirmed");
  - a disagreeing author, or a title under 0.75 similarity, stays below 0.6.

  Two refinements came from looking at real responses and the demo:
  - **Duplicate records of one work are not a tie.** Open Library has several "Pride and
    Prejudice" works by Jane Austen. Picking either can't attach the wrong book, so the
    better-documented record wins. Different works within 0.05 of each other are still a tie.
  - **The same author is not evidence on its own.** A title + author search returns that
    author's other books, so author agreement only counts once the title is close.
  - Also, the filename's raw form is used only when the title came from the filename. A
    translation saved under the original's filename isn't matched to the original.

- **Owner decisions win:** This is it (`user_item.match_override`), Not this one
  (`candidates_rejected`, never accepted again), Leave unidentified, Let the app choose again.
  `MATCH_VERSION` re-scores from the cache with no new requests.
- **Kinds and the reference flag (§8):** a kind from subjects, AniList or a technical publisher
  when the files don't say. The file's own kind (comic archive, ComicInfo manga, comic PDF)
  always wins, and the owner's override wins over both. Reference from title words (Cookbook,
  Handbook, Reference, Rulebook, Dictionary, Encyclopedia, Cheat sheet).
- **Estimates (§12.3–12.4, `lib/estimate.ts`):**
  - Durations as ±20% ranges: words ÷ wpm for prose, pages × seconds for comics and manga.
  - Pages × 275 words, or a source's page count, is always "rough". Only a count from the file
    is "measured", and only measured lengths can be a sure fit.
  - Remaining time from the progress bucket, labelled rough.
  - Effort from kind and reference only (see "Not in M3").
- **Ratings (§12.2, `lib/ratings.ts`):**
  - Normalised to 0–100 and shrunk toward each source's own mean in this library, with the
    source's median vote count as the prior weight. Sources are never pooled.
  - "Highly rated" is the 70th percentile per source, or ≥ 80 with fewer than 30 rated items.
  - Preference: Hardcover → AniList → Open Library.
- **Ranking (§13, `lib/recommend.ts`, pure):**
  - Shared eligibility (finished, Never, hidden, DNF and history-only are out; reference only
    in Skim later).
  - One per series, using the series name from the file or a source.
  - The §20 blend with unknown = neutral. Taste is inert (neutral) until M5. Recency is a boost
    only, so unknown and old get none.
  - Cards state their scope, up to three true reasons, and limitations. Missing data never
    gives a reason; "finish" is only said of a measured length.
- **Lookups (`identify/lookups.ts`):**
  - Run after each scan (Settings can turn that off), or from the banner.
  - Resumable per item and source. Failures retry on the next run.
  - A changed title or author asks again.
  - In-progress and shortlisted books go first.
  - Western comics are skipped until Metron/ComicVine (M4).
- **Needs review (§11.4):**
  - Tier 2: ties and "Wrong book". Tier 3: unconfirmed or unidentified books on the shortlist
    or in progress. Tier 4: other unconfirmed matches. Unidentified books that can wait are
    counted, not listed, because a big library has thousands.
  - Search and pick, Defer (30 days) and Dismiss on every row.
  - **Confirm all like this** for cross-folder suggestions and moves, with a preview. Rows
    where both items have history are skipped and reported. This answers M2's 649 tier-4
    suggestions in one decision.
  - A match-quality and data-coverage summary in the header.
- **Match quality report (§11.5):** `npm run report:matches` runs the matching over 13
  labelled examples on recorded responses, 5 of them held out from tuning. A private set in
  `fixtures/private/match-cases.json` is reported separately when present. In the app, the
  owner's confirmations and rejections are the labels; a rejection of a candidate that scored
  ≥ 0.90 counts as a wrong high-confidence match.

  | Set                | Correct  | Wrong high-confidence | Held out correct |
  | ------------------ | -------- | --------------------- | ---------------- |
  | Committed fixtures | 13 of 13 | 0                     | 5 of 5           |

- **UI:**
  - **What next** is the home page: the time control (30 min … a weekend, Any) with _Read for
    that long_ / _Finish something in that time_, Ready to read, cards, a "Might fit" group
    (rough lengths), Show more, the shortlist star and **Not this, because…** (Already read,
    Wrong book, Not in the mood for this tab only, Not interested → offers Never, Other).
  - **Triage**: one book at a time, W/M/N/R/S and U for undo. Offered once on What next.
  - **Item page**: a "Ratings and details" card.
  - **Settings**: Online lookups, with the Hardcover token masked, Show and Remove.
  - **Diagnostics**: source status and **Test Hardcover**.
- **Schema:** migration `003_lookups.sql`. New owner data (`candidates_rejected`,
  `review_state`, `pick_feedback`, `user_item.match_override`/`wrong_match_at`) and the derived
  matches (`item_matches`, `lookup_state`) are in the backup, so recommendations survive a restore
  without re-fetching. Raw responses (`source_cache`), `secrets` and `enrich_runs` are excluded,
  with reasons. Version-1 and version-2 backups still restore.

Bugs found by looking at the demo, not by tests:

- the same author with a different title reached "provisional";
- a translation matched its original through the filename;

- an availability label lost its capitals ("in icloud").

**Speed** (5,000 synthetic items, 4 vCPU Linux): Read next takes about 200 ms (assembling the
data ~160 ms, ranking ~20 ms). Counting Needs review takes ~150 ms. Counting books still to look
up takes ~400 ms, so it's cached for 30 s. Lookups run at about one book a second, the limit
Open Library sets.

## Not in M3 (by plan, or moved)

- **Effort from a readability sample (§12.4).** It needs another read of every file. On the
  owner's drive that's the 55-minute reading phase again. Effort comes from kind and reference
  only for now, labelled rough. Readability waits for the next deep-pass change that re-reads
  files anyway.
- **Tier 3 "appearing in recommendations".** Tier 3 covers shortlisted and in-progress books. A
  book in the current Read next list with a tie or no match already says so on its card.
- **Series proper** (the `series` table, gaps, collections, publication status on cards) is
  M4. M3 groups installments by series name for one-per-series.
- **Comics lookups** (Metron, ComicVine): M4. Comics rank on time fit, triage and momentum, as
  §13.7 intends.
- **Tune** (adjusting the weights) is M5. The weights are the §20 values in `config.ts`.
- **"Recommended" label on Hardcover.** It shows as _Optional_ until the owner's Test Hardcover
  report confirms that it returns ratings, counts and series for their books (§12.1).

## Hardcover check on the owner's PC (2026-11-09, title-free)

The owner made a token and ran Diagnostics → Test Hardcover:

- The token worked. Three random books from the library returned 2, 3 and 1 results.
- Two top results came back with a rating, a rating count, pages, the year and genres; one also
  had a series position. The third had no rating, pages or year.
- Rating counts were small (1 and 3), so shrinkage toward Hardcover's mean matters for this
  library.
- Rate-limit headers: `x-ratelimit-limit=10` (the burst), `x-ratelimit-reset` in epoch seconds,
  which the client already handles.
- **The response shape matches the adapter, which was built from Hardcover's docs.**

That meets §12.1's conditions: a working token; ratings, counts and series order returned;
limits that suit the library; and terms that allow personal use. Hardcover is now labelled
**Recommended** (still optional) in Settings.

## First lookup run on the owner's PC (2026-11-09)

The owner turned a VPN on partway through. Requests then failed with "fetch failed" (no
connection). No data was lost: failed books stayed on the list and are retried. But the run
had two weaknesses, now fixed:

- **It kept going while offline**, marking the rest of the library failed. A run now stops after
  10 books in a row couldn't reach any source, and says why.
- **A source paused by the circuit breaker stayed paused for 10 minutes**, even after the
  connection came back and the owner pressed "Look them up now". A run the owner starts now
  resets the pauses.

Hardcover requests made before the drop: 402 of the day's 5,000.

## After the first full lookup run (2026-11-09, title-free)

Needs review's header after the run: 1,022 matched · 206 unconfirmed · 103 tied · 410 not found ·
880 not looked up (mostly comics, skipped by design). From the owner's screenshot of the ties,
two causes, both fixed (`MATCH_VERSION` 3: the next run re-scores from the cache, no new
requests):

- **The same book entered twice at a source**, once with its subtitle in the title and once
  without, by the same author, was a tie. Such records are now one work; the better-documented
  one wins. Two _different_ subtitles stay a tie.
- **Single issues looked up as books.** A file numbered like a comic or magazine issue
  ("Series #48") of unknown kind was searched on the book sources, which return unrelated
  novels with that name, so it tied. Issues now wait for the comic sources (M4), and
  candidates from sources that no longer apply are dropped when the next run starts.
- A title matching only once a subtitle is dropped ("Title" vs "Title: Subtitle") now scores at
  most 0.85, so it can be unconfirmed but never certain: a sequel sharing the main title must
  not be accepted.
- Needs review now counts comics and issues separately ("looked up from Milestone 4") instead
  of under "not looked up yet". Also "1 rating", not "1 ratings".

## First look at the picks (2026-11-09, title-free)

After the re-run: 776 matched · 186 unconfirmed · 75 tied · 288 not found · 1,296 comics and
issues. What next offered 1,461 books; 460 had a rating and 1,366 a known length. The owner's
screenshots showed four problems, all fixed (`MATCH_VERSION` 4):

- **Volumes of one series tied.** "Series 24" matched "Series, Vol. 24" and "Vol. 32" equally,
  because volume numbers weren't compared. Different numbers now rule a candidate out. Comic and
  manga volumes search the book sources with their number.
- **A book entered twice at a source, once with no author,** was still a tie. Now it's one work.
- **A comic PDF with a thin text layer** was read as "~5 min from 741 words" and guessed
  "Fiction" from its subjects. A PDF of 20+ pages with under 50 words a page is now measured from
  its pages ("mostly pictures", rough) and guessed as a comic.
- **Comic volumes and manga** were left to AniList (series scores only) or skipped. Hardcover rates
  each volume, so they now go to the book sources too; AniList still gives manga its series data.
  Only single issues wait for Metron/ComicVine (M4).
- **The owner asked for a Books / Comics and manga / Both choice** on What next. Added.

Noticed, not fixed yet: some titles from filenames lose an "&" ("Locke Key") or split oddly
("Mort Y"). That's a filename-parser change, for the next parser revision.
