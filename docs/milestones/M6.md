## What was built

### Stats (§15) — `server/src/lib/stats.ts` (pure), `/api/stats`, `web/src/pages/Stats.tsx`

Facts first, estimates apart and labelled.

- **Facts:** books finished per year with the kinds; this year so far against last year by the
  same date (finishes whose date is too rough to place — a month equal to this one, or a year
  only — are counted apart); read rate by kind and by folder, always "N of M"; DNF reasons
  ("no reason given" included); Never totals by kind; your ratings (count, average and a 1–10
  bar list with the numbers as text); takeaways; data coverage by kind; the match summary;
  what taste has learned (linking to Tune).
- **Estimate:** the backlog's reading time by kind — only books with a known length, how many
  that is ("25 of 30"), and for books in progress only what's left (rough, from the bucket).
- **Rules:** only what the owner marked counts, so a collection's issues read "via collection"
  add no finishes (scenario 20); a finish with no date is listed apart and counted in no year
  (scenario 6); Never and reference books are left out of the backlog and the page says how
  many; no page counts read are shown (buckets can't give them). Read-elsewhere books count as
  finishes (they are readings) but never in "books you own" or read rates.

### CSV export — `server/src/lib/export.ts`, `/api/export/csv`

One row per book (owned and read elsewhere): title, author, kind, progress, dates, rating, Want/
Maybe/Never, shortlist, series and number, ISBN, formats, where it is, stores, acquired date,
first publication, community rating with votes and source, estimated length and its basis,
note, takeaway, id. The first columns share the store-CSV import's names. A first line says it
isn't a backup. Unknown dates stay empty. Cells starting with `= + - @`, a tab or a carriage
return get an apostrophe so a spreadsheet never runs them as formulas (titles come from files
and other people's data). UTF-8 with a BOM and CRLF, so Excel on Windows keeps accents.

### Full local snapshot (§16) — `server/src/lib/fullSnapshot.ts`, `/api/snapshots/full`

Settings → Export and snapshots → **Take a full snapshot**: the database (through SQLite's backup
API, never a file copy) plus the covers, in `data/full-snapshots/full-<time>/`, with a
`README.txt` saying how to go back to it. **API keys are deleted from the copy and the file is
vacuumed**, so no key is left in free pages (tested by searching the bytes). Written to a
`.partial` folder first and renamed when complete. The newest 3 are kept (`FULL_SNAPSHOTS_KEPT`,
an assumption). Refused while a scan runs (covers are being written); lookups may run.

## PR review corrections

An AI review of PR #7 found three real problems, all fixed with tests:

- **Two snapshots at once** could share one `.partial` folder (names are unique only to the
  millisecond) and both fail. Snapshots now run one at a time per data folder, and each claims
  its folder exclusively, adding "-2", "-3"… on a collision.
- **Diagnostics said Open worked when the launcher hadn't started.** Both platform adapters
  discarded spawn errors. A shared `platform/launch.ts` now waits until the OS has started the
  launcher or refused; a refusal is a plain error to the owner and a failure in Diagnostics.
  It still can't know whether an app then showed the book (explorer.exe exits with 1 even when
  it succeeds), so Diagnostics says "the system started it — check that the book appeared".
- **A failed file check left the previous success showing.** Every Open / Show attempt is now
  recorded, its drive and file checks included. Stopping to ask before a cloud download is
  shown as that, not as a failure.

## Fixes from the owner's testing

Two problems found on the real library (described without titles):

- **An "optimized" copy of a comic volume was its own book, outside its series.** Two causes.
  "optimized" (and "opt", "downsampled", "lowres", "-low", "-high") was stripped as a tag but
  not recorded as the file's _quality_, and two files in one folder group only when their
  format or quality differs — so `book2.pdf` + `book2_optimized.pdf`, both PDFs, never grouped.
  And underscored markers split from their number ("Name_Book_2", "name_vol_2",
  "name_book_two") lost the series and number altogether. `PARSER_VERSION` 7 fixes both: size
  versions are qualities, a reduced copy never opens first, and "Book"/"Vol" read the next
  segment (digits or "one"–"twelve"). The next scan re-reads every name.
  Entries that are already apart in the same folder are **suggested, never joined silently**
  (an owner's split must not be undone): Needs review, tier 2, "Another version of this book
  in the same folder (optimized)", with Group / Keep apart. Before, same-folder pairs were never
  suggested at all.
- **"Published volumes: Couldn’t confidently identify this series" every run, for the same
  series.** A failed check was never remembered, so each lookup run asked again and listed it
  again ("need checking for 13 series" never went down). Migration 012 adds
  `series_publication_problems` (excluded from backups as retry notes): a failure that retrying
  won't fix is remembered until the series' anchor book or number changes, or 7 days pass; the
  series page's button always asks again. The message now names the series. And the series
  choice is a little less strict: when Hardcover's series name differs from the files' (the
  match was exact-name only), the confirmed book's **only** real series, **at the same number**,
  is accepted. Two series, a different number or a compilation still refuse.

- **"Check published volumes now" seemed to do nothing.** Answers came from the cache, so a
  run finished in milliseconds and the banner looked the same (same count, same errors). The
  banner now says what the run did ("✓ Done. Checked published volumes for 13 of 13 series").
- **More filename shapes:** a spaced en/em dash ("March – Book Two") separates like " - " (it
  was left on the series name), and a full stop or semicolon before "Book" no longer stays on
  the series name.
- **The optimized copy's real name was "name_booktwo_optimized".** Parser 7 already reads it as
  volume 2, optimized; grouping keys now also read a number word after "book"/"vol" as its
  digit, so it pairs with "name_book2" in the same folder.
- **186 ties in Needs review** were mostly the same thing: a file read as "Series: Book Three"
  had no number for the matcher, so "Series" and "Series, Vol. 2" tied with it on title alone;
  and Hardcover's "Series: Book Two" looked number-less too. `MATCH_VERSION` 10 reads "Book
  Two" / "Volume Three" as numbers on both sides: a different number drops to 0.3, the same
  number is a full title match. Rescored from the cache on the next lookup run, no new
  requests. Match report: 13/13, 0 wrong high-confidence.
- **Ties that remained (183)** included a comic with a story name ("Series: Arc A") tying with
  "Series, Vol. 2: Arc B", and "Series #1" tying with "Series 8 #1". `MATCH_VERSION` 11: two
  different story names are two books (comics and numbered volumes only; "A Novel"-style
  subtitles don't count), and a bare trailing number is part of the series name when "#1" or
  "Vol." already marks the number. Two runs with the same name and no year in the file
  ("Series #1" from 1996 and from 2016) stay a real tie: only the owner can say.
- `MATCH_VERSION` 12: a named book with no number ("Series: Exclusive Art Book") is none of the
  series' numbered volumes ("Series, Vol. 7"), unless that volume carries the same story name.
  It tied with every volume before.
- `MATCH_VERSION` 13: when the tied candidates each match only part of our title — ours names
  something theirs lacks ("Name: Subtitle" against several unrelated "Name!") — and no author,
  ISBN, year or run agrees, the book is "not found" instead of a tie. A shorter title of ours
  against longer records stays a real question. One book listed twice at a source with a
  misspelt or HTML-encoded author ("&#322;") is one book: Open Library and Hardcover text is
  now entity-decoded, and the same full title with near-identical surnames counts as one work.

## Hidden gems loosened (after Stage 3)

The owner's library had **no Hidden gems**, before and after Stage 1 (Diagnostics comparison,
2,593 items). Two causes: the gem test used the adjusted score, which pulls few-vote books to the
source's average, so a gem could hardly count as highly rated; and "few" was the bottom 25% of
each source's counts, which in a library of mostly small counts fell below the 5-vote minimum.

Now: the source's own score must reach its "highly rated" line and the book must stay above the
source's average once adjusted; "few" is the bottom half for its source or 25 votes, whichever is
higher (`HIDDEN_GEM_VOTE_PERCENTILE = 0.5`, `HIDDEN_GEM_FEW_FLOOR = 25`); at least 3 votes
(`HIDDEN_GEM_MIN_VOTES = 3`). Still: trusted matches only, never a whole-series score, few on
every other trusted source. All three numbers are assumptions in config.ts and PLAN.md §20.

The before/after comparison freezes M6's gem rule (bottom 25%, at least 5) in
`lib/ratingComparison.ts`, so Diagnostics → Compare shows the change: on the invented fixtures,
Hidden gems goes **1 → 4**. The demo keeps populated and empty cases. `npm test` 528 passed.

Owner check: Diagnostics → **Compare with the old rating order** → the Hidden gems line, then
open What next → Hidden gems.
