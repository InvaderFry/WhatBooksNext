# Milestone 1: library and tracking

**Status:** built. All the done-when checks pass in this environment (Linux sandbox). The
Windows-only behaviour listed below still needs checking on the owner's PC.

## What was built

- **Repo:** npm workspaces (`server`, `web`), TypeScript 6, ESLint, Prettier and Vitest. CI runs
  test, typecheck, lint, format and build on Ubuntu and Windows. The server runs as TypeScript on
  Node 24's type stripping, so it has no build step. The licence is PolyForm Strict 1.0.0.
- **Native module:** better-sqlite3 13 ships Node-API binaries for win32-x64 inside the npm
  package. This was checked in the published tarball. No build tools are needed on Windows, and
  any Node from 22 on works. `engines` asks for ≥ 24, the current LTS line.
- **Startup:** `start-whatBooksNext.bat` checks that Node is installed and ≥ 24. `scripts/start.ts`
  checks that the port is free, runs `npm ci` when the lockfile changes, builds the pages when
  their sources change, starts the app and opens the browser. The app binds to `127.0.0.1:4818`.
- **Request checks (§6.3):** the Host header must be the app's own. State-changing requests must
  be `application/json` and must not carry a foreign Origin. OPTIONS gets a 403 and no CORS
  headers are ever sent. Vite's port is allowed only with `WBN_DEV=1`. Uploads are read in the
  browser and sent as JSON. Pages get CSP, `X-Frame-Options` and `nosniff` headers.
- **Database (§6.2):** numbered SQL migrations, each in its own transaction. Before migrating a
  database that has data, an Online Backup API snapshot is taken (the last 5 are kept). A failed
  migration stops the app and names the snapshot to restore.
- **Platform adapters (§9.4, §9.5, §14):**
  - Windows: one long-lived PowerShell helper (`-EncodedCommand`, JSON lines). Directory
    listings return names, sizes, dates and raw attributes from the listing itself, so the light
    pass never opens or `stat`s a file. It also handles single-file attribute re-checks, volume
    identity (`Win32_Volume` GUID and serial, `Get-Partition | Get-Disk` bus type) and finding a
    volume on a new letter.
  - External drives are recognised by **bus type**, because the owner's USB drive reports
    DriveType Fixed (M0).
  - Open uses `explorer.exe <path>`, and Show in folder uses `explorer.exe /select,"<path>"`.
    Both take file ids, never paths.
  - A generic adapter (macOS/Linux, untested) and a fake for tests and the demo complete the set.
- **Light pass (§9.2, §9.3):** files are marked missing only when their own directory, or the
  nearest listed ancestor, was completely listed. Unlisted directories are left as they were and
  flagged stale. Cancel stops after the current directory. Unreachable folders are skipped and
  reported. A file that becomes present again has its deep-pass stages reset. A partial scan
  doesn't move "last complete scan". `.zip` and `.rar` count as CBZ and CBR, as the owner
  confirmed.
- **Filename parser (§11.1):** follows the plan's fixture table, the patterns added after M0
  (download duplicates, size tags, Humble ids, trailing article, `V1 17`, trade hints, edition
  words, issue words) and wordninja-style splitting of run-together names (MIT word list).
- **Grouping (§11.3 rules 1–2):**
  - Copies: same name and size in any two directories, with no disagreeing hash.
  - Format groups: same directory and base name, with quality tags ignored.
  - Grouping is chained across folders and carries history across moves. Known edition
    conflicts block it, and empty files never group.
  - A file that links to two existing items gets its own item (cautious).
  - Primary file: present files first, then EPUB for prose or HD for comics.
- **Library and owner data:**
  - Search ignores spaces, so "mapmaking" finds "Map Making".
  - Filters: kind, progress, format, availability, folder, Ready to read, shortlist. Sorts:
    title, first seen, last touched, rating.
  - Item page: one-tap progress, DNF reasons, start and finish dates with
    exact/approximate/unknown precision (never today as a stand-in), rating, note and takeaway.
  - Corrections and overrides: title and kind fixes, the reference flag, "Also in iCloud"
    (per folder, with a per-item override), hiding a book.
  - Shortlist with accessible ↑/↓ buttons.
  - Settings: add, reconnect and remove folders, Scan now or scan one folder, last-scan details.
  - Diagnostics, with a copyable report that leaves names out unless asked.
- **Backup and restore (§16):**
  - Backups are JSON. Restore replaces everything: validate, preview (including "changed since
    the backup"), take a pre-restore snapshot (last 3, kept apart from the migration ones), then
    apply in one transaction with a foreign-key check, rolling back on any failure.
  - `scan_runs` and `directory_scans` are left out, with the reason written down. A test fails
    if any table is in neither list.
- **Demo (`npm run demo`):** an invented, clearly labelled library covering:
  - a format trio and an HD + standard pair;
  - a copy in a "cloud" folder that is online-only;
  - separate 2nd and 3rd editions;
  - an unknown-state file, a missing file and a disconnected drive;
  - some reading history.

Bugs that only the browser check found, now fixed:

- After first-run setup the library stayed empty, because a small scan finished before the UI's
  first poll.
- The restore confirmation vanished because the page remounted.
- On phones, shortlist rows squeezed the title.
- Every file row had buttons named just "Open", so screen readers heard duplicate names.

**Light-scan measurement:** 5,000 synthetic book files in 400 directories took 1.34 s for the
first scan and 0.81 s for a rescan, grouped into 2,600 items. Measured on a 4-vCPU Xeon
2.1 GHz Linux sandbox with the generic adapter, against the 30 s target in §20. **This isn't a
Windows number.** The Windows path makes one PowerShell round trip per directory. M0's
PowerShell-only listing of the owner's drive (474 directories, 7,963 files) took 7.9 s, which
suggests the same order of magnitude. Proper benchmarks come in M2.

## The owner's first real scan (title-free)

- **Windows:** the start script installed and ran on Windows 11 with Node 26.13, after a fix for
  npm compiling better-sqlite3. The project's `.npmrc` now skips install scripts, because the
  library ships its own binaries.
- **Drive:** recognised as **External drive** with its volume identity (the USB bus-type rule
  works). The folder was found at `E:`.
- **Scan:** a few seconds for 4,026 book files (the M0 count of 3,842, plus 184 `.zip`/`.rar`
  comics). No missing or stale files. 2,664 items, in line with the expected ~2,400–2,700.
- **Grouping:** 949 items have 2 files, 35 have 3, 92 have 4, and 14 have 5–8. The 5–8-file
  groups checked by hand were all the same book bought in several bundles: copies across bundle
  folders plus their EPUB+PDF pairs. None was wrong.
- **Titles:** the owner's backup was checked privately against the parser. Problems found:
  - `Series - 12` read as a book titled "12" (a whole manga run);
  - `Series - Subtitle` comics losing their subtitle (many different specials showed the same
    title);
  - two-digit comic issues not recognised;
  - years read as issue numbers;
  - `-low`, `_new` and dashed Humble ids left in titles;
  - volume ranges (`1-25`);
  - `Book 1 - Title`;
  - hyphens inside words being dropped.

  All are fixed in parser version 2, with invented-name tests. 137 of 2,664 titles change; every
  change was reviewed and was an improvement, with a few cosmetic leftovers. Run-together names
  still split badly sometimes ("in u ya shiki"). That's expected for a filename guess: the
  file's own metadata (M2) and online lookups (M3) fix these.

- **Refresh:** every file now records the parser version that read it. The next scan re-reads
  names from an older version and refreshes those titles. Owner title fixes are never touched.
